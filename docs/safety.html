Before you write

Safety

Three different “look first” modes, plus quarantine for files that won’t open cleanly. Mixing them up is the main source of surprise.

Overwrite vs keep originals

Default behavior writes fixes over the input files. There is no automatic backup.

  • -o DIR — write tidied fonts into a new directory; leave inputs alone.
  • Without -o — originals are replaced when handlers apply changes.

-n vs --validate-only

FlagOpens fonts?Applies fixes?Use when
-n, --dry-run No No You only want the file list and which handlers would run
--validate-only Yes No You want a real problem report before writing
Common mix-up. -n never opens a font. If you need to see what’s wrong inside the tables, use --validate-only (often with -v).

Quarantine

When a file looks corrupted or fails to open, FontFixer moves it to <input>/_quarantine/ by default so a bad file doesn’t sit mixed with clean ones.

  • Default — quarantine enabled
  • --no-quarantine — leave the bad file where it is

Suggested first pass

# 1) What would run?
fontfixer -n -r fonts/

# 2) What’s actually wrong?
fontfixer --validate-only -v -r fonts/

# 3) Write somewhere safe
fontfixer -o tidy/ -r fonts/
